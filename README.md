# MUSIM.CO

AI 운동 자세 교정 웹 서비스를 주제로 한 졸업작품 팀 프로젝트로, 백엔드 개발을 맡아 실시간 운동 횟수 측정 API와 사용자 활동 기능을 구현하고 프론트엔드와의 협업 방식을 조정해 기한 내 시연 가능한 결과물을 완성한 프로젝트입니다.

---

## 프로젝트 개요

- 기간: `2025.04 ~ 2025.11`
- 형태: 졸업작품 팀 프로젝트
- 팀 구성: 프론트엔드 3명, 백엔드 2명, AI 담당 1명, 총 6명
- 기술 스택: `Python`, `Flask`, `MySQL`
- 핵심 주제: 팀 프로젝트, API 협업, 실시간 운동 횟수 측정, 우선순위 조정

## 프로젝트 소개

`MUSIM.CO`는 사용자가 헬스장에 방문하지 않아도 AI를 통해 운동 자세 피드백을 받을 수 있도록 설계한 웹 서비스입니다.

- 운동 설명 영상 제공
- 사용자 영상 업로드 기반 AI 자세 교정
- 웹캠 기반 실시간 운동 횟수 측정
- 데일리 미션 및 출석 기반 포인트 지급
- 회원가입 및 로그인 기능

이 프로젝트는 졸업작품으로 진행한 팀 프로젝트이며, 제한된 기간 안에 핵심 기능 구현과 시연에 집중해 완성했습니다.

## 기술 스택

### Database

## 주요 기능

- 웹캠 프레임 분석 기반 실시간 운동 횟수 측정 API 구현
- 크런치, 레그레이즈 운동에 대한 상태 판별 및 횟수 카운트
- 데일리 미션, 포인트 보상, 출석 체크 기능 구현
- 포인트 랭킹 조회 기능 구현
- 운동 영상 탐색 기능 구현: 검색, 정렬, 필터
- 프론트엔드와 API URL, 요청/응답 JSON 구조 협의

---

## 주요 기능 흐름

이 프로젝트는 `실시간 운동 횟수 측정`, `사용자 활동 기능`, `프론트엔드 연동`이 중심이었습니다.

- 사용자가 웹캠으로 운동을 수행하면 프레임 데이터를 기반으로 운동 상태를 판별
- 관절 각도 변화에 따라 운동 횟수를 카운트
- 데일리 미션, 출석 체크, 포인트 보상 기능과 연결
- 프론트엔드와 사전에 정의한 API URL 및 JSON 구조를 기준으로 병렬 개발 진행

---

## 시스템 구조

`Frontend -> Backend(Flask) -> MySQL`

- `Frontend`: 사용자 입력, 운동 화면, 결과 화면 구성
- `Backend`: 운동 횟수 측정 API 및 사용자 활동 기능 처리
- `Database`: 사용자 정보, 포인트, 활동 데이터 저장

## 문제 상황

프로젝트 초반에는 백엔드에서 API를 먼저 구현한 뒤 URL과 JSON 데이터를 프론트엔드에 전달하는 방식으로 협업했습니다. 이 방식에서는 프론트엔드 개발자가 API 구현을 기다려야 했고, 데이터 구조가 바뀔 때마다 반복 수정이 발생했습니다.

또한 첫 발표 이후 주제가 변경되면서 개발 기간이 부족해졌고, 제한된 기간 안에 핵심 기능을 우선 구현해야 하는 상황이었습니다.

## 해결 방법

프론트엔드 개발자와 협의해 협업 방식을 바꿨습니다.

- API URL을 사전에 정의
- 요청/응답 JSON 구조를 사전에 정의
- 이를 기준으로 프론트엔드와 백엔드가 병렬 개발

또한 기능 구현이 지연되는 상황에서는 처음 계획한 모든 기능을 그대로 유지하기보다, 발표 시점까지 반드시 보여줄 수 있어야 하는 핵심 기능 중심으로 우선순위를 조정했습니다.

- 실시간 운동 횟수 측정
- 데일리 미션 및 포인트 시스템
- 서비스 시연이 가능한 핵심 흐름 완성

프로젝트 진행 중 AI 자세 교정 기능 구현이 지연되었을 때는, 내가 맡은 기능을 먼저 완료한 뒤 일부 기능 구현을 함께 진행하며 작업을 분담했습니다.
